# 后台用户、岗位权限与自动工作区 V1

日期：2026-10-07。依据本会话用户确认的三甲医院病理科岗位设计和“修改代码”授权。仅在现有合成 dev/test 系统实现，不改变临床启用、电子签名或生产部署边界。

参考：[病理科建设与管理指南](https://www.nhc.gov.cn/zwgk/wtwj/201304/b67e2ccc097948109e33d80781b77f79.shtml)、[2024年病理专业质控指标发布通知](https://www.nhc.gov.cn/yzygj/c100068/202405/7d1d82090e8b44d2af3339d7ee8c7cca.shtml)。角色组合是本系统设计，不作为医院正式岗位或资格审批证据。

## 验收

- 独立医院级管理员管理本院合成账号；新增、编辑、停用、重置密码、岗位与逐项权限设置、默认范围配置可通过页面完成。
- 预设系统管理员、科主任、登记接诊、取材医师、常规技师、细胞学技师、特殊染色技师、冰冻技师、分子病理技师、诊断医师、复核签发医师、质控、报告档案、审计岗位。分子功能尚未实现，不虚构操作权限。
- 管理员有全部管理权限及可配置的业务权限。诊断、复核、模拟签署仍需要显式有效资格；管理员角色不自动生成医师资格，不绕过原职责分离、状态、版本和审计。
- 每名用户可拥有多个范围及一个默认登记范围。普通工作区删除范围选择器，自动载入服务端确定的范围；多范围申请查询汇总已授权数据，既有申请操作使用其原范围。
- 管理范围可创建、重命名和停用。医院、院区、科室、来源关系受复合约束保护，已建立范围的组织身份不可变。
- 账号和授权变更带 expectedVersion、理由、幂等键；事务内锁定管理员授权与目标，CAS、变更原因记录、成功审计、幂等回执一起提交。禁止跨医院替换 ID、普通用户直调和管理自己的管理权限。
- 密码只存 bcrypt；初始/重置密码要求首次修改。停用、重置和授权改变更新 auth_version，旧会话失效；密码和正文不进审计。
- 不迁移历史账号为管理员；首个管理员必须由显式本机初始化步骤指定，迁移不带账号或密码。

## 界面

后台包括用户管理、岗位权限、组织与工作范围、管理审计四项。继承现有 Ant Design 与深青色侧栏。历史 UI-033 的索引存在，但本机未找到该原型图片；本次采用用户授权的新后台布局，不声称复刻历史原型。业务范围显示为只读工作区信息，不在业务步骤中授予权限。

## 验证重点

真实 PostgreSQL 空库与 V37 升级、账号与组织约束、未授权/跨医院/撤权重放、同键异参、并发版本冲突、审计失败回滚、管理员无资格签署拒绝、停用和重置后的旧会话、首次改密门禁、默认范围无效时拒绝、跨范围查询隔离；前端取消/迟到、失败非空数据、未知结果原键重试与表单切换清理。执行证据另记 docs/api/identity-administration.md。
