# T26 归档、借阅、归还与盘点开发 PRD v1

2026-10-03，依据用户 T26 明确授权；仅合成开发规格，医院保管、借阅资格、期限、法律保全和物理核验制度未批准。原执行环境已查看授权 UI-026 档案入库与定位和 UI-027 借阅归还与到期实际图片。沿用逐项扫码、独占槽位、部分归还、异常留存；不采用原型虚构统计。

## 模型与验收

- 每个已接收申请一个档案台账，稳定医院/组织/病例/患者关联。档案项只登记既有蜡块、玻片或确切不可变报告产物，一来源只登记一次；报告保留修订ID、产物ID、版本和SHA256。没有内容重渲染接口，不改变既有PDF授权。
- 独立合成档案资格（申请、审批、管理权限）与原有组织范围同时有效，管理员不自动获得权限。提交及幂等重放重查账号、资格和原病例范围；资格记录在事务中锁定。借用者必须是同范围有效合成人员，不产生新权限。
- 人工创建稳定位置ID与开发库位代码；上架、下架、移位/移交需扫码、原因、确切版本。每个槽位至多一个档案项。所有记录仅声明人工登记，独立物理确认保持未验证。保管策略标签与法律保全是开发元数据，无销毁能力。
- 申请借阅需目的、借用者、明确带时区到期时间、确切项/版本。期限受可配置开发上限约束（默认30天不是医院规则）；申请即预约，唯一占用。审批由具审批资格且不同于申请者的人员明确操作。逐项借出/归还支持部分完成；拒绝/取消仅释放未借出的预约，不释放遗失/在借项。旧请求不能重新占用。
- QC不合格、隔离、作废仍能归档、归还和追溯；禁止借出。借出重新读取当前来源QC/身份；不得因归档放宽原有临床消费门禁。
- 遗失、损坏、找回均追加事件。遗失在借项仍占用，找到后仅记录为待核对，必须明确归还；损坏不自动恢复可借。恢复状态只限人工保管记录，不改变原材料QC。
- 盘点冻结明确项ID/版本/位置/状态；逐项扫码核对、差异说明独立追加。项发生变化即旧快照失效；更正需引用差异、当前版本、原因和目标位置，不删除原盘点或静默更改数量。每档案项固定1件，无自动增减。
- 申请根锁与台账CAS，逐项状态/独占约束、业务事件/审计/幂等同事务。批量最多10条，同病例，逐项独立事务和授权，结果为SUCCESS/FAILED/UNKNOWN/NOT_ATTEMPTED；未知失败停止后续，不将未执行项标成功；重试各条原键。
- 界面显示身份、确切版本、位置、保管状态、借阅状态、人工与物理确认差别。切动作/病例提示脏数据，迟到读取丢弃，未知写入保留原键与全部输入；服务器冲突不静默覆盖。

## 验证与排除范围

覆盖双预约/借出、CAS、条码、部分归还、跨范围/撤权、QC变化、快照失效、追加历史、审计失败回滚及UI迟到/取消/重试。仅本地合成数据，无设备、通信、外部分享、实际销毁、临床/CA签署和部署。默认合成开关关闭。完整后端与真实E2E若受既有BOM缺失阻塞须明确报告；局部检查不代表可合并或投产。
