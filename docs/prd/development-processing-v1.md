# T12 开发规格：技术任务与人员交接 V1

2026-10-02，用户授权补充开发PRD。已在当前环境重新下载并验证原型ZIP摘要，实际查看UI-010脱水批次、UI-011包埋工作站、UI-012切片与重切。仅默认关闭的合成dev/test，不代表医院工艺或临床制度批准。

## 范围与身份

基于T11已完成取材记录、有效PLANNED取材盒建立独立技术任务UUID。任务类别PROCESSING/EMBEDDING/SECTIONING仅表示技术队列；不创建实际蜡块、玻片、重切编号或设备作业，这些实体属于T13。一个盒可有不同类别和返工任务，来源盒/容器关系保持稳定。

创建须有原因，可选择同一盒的前置任务，前置必须SIMULATED_DONE；无前置也必须说明路线，允许直接工位/不同流程，不能把常规处理→包埋→切片设为所有标本的强制临床路线。每病例最多50个任务（含终态），列表按病例有界。当前没有跨病例设备批次或真实工艺参数，原型设备运行/预计完成时间不作为真实状态展示。

## 状态和交接

- QUEUED→ACTIVE：当前有PROCESS权限的用户核对确切盒UUID后领取；owner由服务器设置。
- ACTIVE→HANDOFF_PENDING：当前owner另有HANDOFF权限，填写交接原因发起交接，未接收前仍属于原owner，禁止完成。
- HANDOFF_PENDING→ACTIVE：另一个当前有PROCESS+HANDOFF权限的用户，核对确切盒UUID并填接收说明后确认，原owner不能自己确认。双方身份和时间进入追加事件。未定向指定接收人，只对同授权范围有效账号开放；医院岗位/资格另批。
- 原owner可取消待确认交接，回到ACTIVE并追加原因，不能删除交接轨迹。
- ACTIVE→SIMULATED_DONE：仅当前owner显式核对盒UUID并记录合成演练完成。永不表示真实脱水/包埋/切片完成，无计时器、动画或模拟设备回执自动推进。该状态仅作为本开发技术任务的前置条件。
- QUEUED可以中止；ACTIVE/HANDOFF_PENDING只能由当前owner中止，原因必填，变为ABORTED。终态不可重新打开或覆盖。
- ABORTED/SIMULATED_DONE允许有原因创建返工子任务，新UUID、QUEUED、同盒同类别同前置，reworkOf保留原任务；每任务最多一个直接返工子任务，后续返工沿链追加。创建返工校验原版本并增加其版本/事件，原历史和终态保留。

所有操作reason1–2000字，非创建命令携带expectedVersion及confirmedCassetteId；不接受客户端owner/actor/医院/病例。创建传requestVersion、cassetteId、kind、可选predecessorId、reason；返工不接受替换来源。

## 安全与一致性

READ+PROCESS独立授权（迁移默认false），交接另需HANDOFF且依赖PROCESS。管理员不默认获得技术权限。合成账号和dev/test开关沿用，病例范围服务端校验，跨盒/病例前置、撤权、旧版本、非owner完成均拒绝。创建和写入同事务校验最新取材来源、身份、状态、版本，固定锁顺序主体→scope→grant→申请→任务。描述/来源由Gross公开只读契约提供，不依赖其内部持久化实体。

事件、当前任务、通用审计及幂等回执同事务，审计失败全部回滚。幂等摘要绑定完整输入、动作和资源；重放重新鉴权。相同版本并发领取/接收/返工只允许一个胜出。读视图锁申请以防混合版本；查询有界，前端未知结果冻结输入并保留原键，切任务/范围时清理表单。

V9增量迁移不改V1–V8，不创建账号/权限/业务种子。交接演示第二账号仅存在测试classpath，正常JAR不包含测试账号。
