# T13 开发规格：蜡块/玻片身份与重切谱系 V1

2026-10-02，用户授权补充开发规格；已实际查看合法上传的UI-011包埋、UI-012切片与重切，T10标签原型沿用既有对照。默认关闭、仅合成dev/test；实体表示开发登记，不证明实物制作或医院工艺验证。

## 明确路径

- BLOCK：从T11有效取材盒及T12同盒EMBEDDING/SIMULATED_DONE任务登记合成蜡块。核对盒UUID，任务只允许登记一个蜡块；不修改盒ID。任务、医院、申请、病例、取材记录、盒必须一致。
- SLIDE/BLOCK_BASED：从有效蜡块及同盒SECTIONING/SIMULATED_DONE任务登记原始玻片。蜡块保持稳定，玻片独立UUID。此任务允许一个技术任务登记多张不同玻片，每次命令必需原因及明确输入，不定义临床数量/厚度。
- SLIDE/DIRECT_CYTOLOGY：明确选择细胞学直制，从已接收容器登记玻片，无蜡块/取材盒/技术任务；不是“缺少蜡块”异常。T12尚无直接容器任务模型，因此本路径只验证接收来源与手工合成登记，不冒称工艺前置完成。不能从未知路径自动推断常规或直制。
- RECUT/DEEPER：仅BLOCK_BASED原片/既有重切片支持，核对源玻片UUID、同一有效源蜡块和同盒已完成合成切片任务；新建玻片UUID/显示号/条码，记录源玻片、源蜡块、操作类型和必填原因。源玻片可已作废（历史指引，不作为实际材料来源），源蜡块必须有效。原身份不复用。直制再次制片需另建明确DIRECT_CYTOLOGY原片，不伪装有蜡块的重切/加深。

UUID与显示号分离；显示号DEV-B-UUID、DEV-S-UUID具数据库唯一约束，不使用max+1。条码复用T10受限Code39+Mod43，并登记在同一label_identity全局唯一表中，实体创建时就绑定稳定条码；重复命令返回原实体。医院编号规范另批。

## 作废与反查

每实体ACTIVE/VOID并带版本。作废需要最新版本、确切实体核对和原因，保留身份/编号/来源/事件。作废蜡块同事务作废其所有有效玻片并逐项留SOURCE_VOIDED事件/版本；已有作废玻片不重写。作废单张玻片不作废其他重切片，因为它们实际材料来源是蜡块，历史源片仅为追溯指引。所有新制片/重切/标签预览和重打都重新检查源蜡块及实体状态。无恢复或身份改写接口。

按授权病例查询材料列表（最多100实体）；按实体UUID或精确条码反查当前身份、源盒/容器/任务/蜡块/玻片及最近100条事件；未授权不泄漏存在性。来源同患者/医院/申请/病例由复合FK和原子用例校验共同保证。

## 标签复用

扩展T10同一label_identity/label_job/label_job_event与既有PRINT/REPRINT权限、CSRF、幂等、状态/失败/重试/取消协议，保留旧容器接口与迁移数据。新增材料目标，不新造“已物理打印成功”状态。重打只创建新标签任务并复制原实体/条码/模板快照，不能新建蜡块/玻片。预览/浏览器打印前重新鉴权并检查材料仍有效；已打印纸面无法远程撤销。

标签域通过公开subject provider接口取得材料快照，避免label与material服务循环依赖；材料域通过label公开登记接口分配稳定身份，禁止直接操作其他域内部Repository。前端沿用T10预览/Code39/打印触发逻辑，不调用真实设备。

## 原子与验证边界

新增MATERIAL独立权限且要求READ；标签仍需PRINT/REPRINT。服务器决定actor、组织、患者、病例、实体类型与谱系。所有创建包含来源版本/确切核对ID/原因；源技术任务及来源状态在锁定申请后重新核验；作废、重切涉及原版本CAS。锁顺序主体→scope→grant→申请→材料（UUID序）→标签任务。当前授权、业务变化、追加事件、审计、回执同事务；失败回滚，重放重新鉴权。

V10增量迁移，不改V1–V9。label扩展保留历史和旧容器约束；迁移需要锁表，只在当前合成小库验证，真实大库上线需评估锁与expand策略。全量真实PG空库/升级/校验和/跨来源FK、并发创建/重切/作废、审计失败、幂等、低权限HTTP与跨病例反查、T10兼容、真实UI/API闭环由验证分支CI验收。

待批准：医院编号/标签、材料留存/作废权限和复核、工艺/厚度/层面/固定条件、真实批次/设备回执、直接制片任务和特殊流程、临床验证。未知路线保持不支持，不产生虚假实体或制作成功声明。无部署/真实患者/设备。
