# T14 技术QC、隔离与返工开发规格 V1

2026-10-02，用户授权开发规格；仅合成 dev/test，默认关闭。当前环境重新验证上传 ZIP 摘要并实际查看 UI-014 制片质检与交片、UI-037 异常与并发弹窗。原型的交片批次、医院缺陷标准、临床放行不自动转为已实现规则。

## 判定对象与标准

每次QC针对确切 T13 材料UUID/版本，记录患者、病例、源盒/容器、源技术任务UUID/版本（直制没有技术任务）、操作者、服务端时间、标准版本与原因。仅支持固定合成标准 SYN-MATERIAL-QC-1；没有批准的医院标准不推断合格。判定 PASS、FAIL、PENDING、IDENTITY_MISMATCH，均需显式选择及原因。追加新判定，不改旧结论；当前指针和版本单独维护。来源改变后旧结论失效，不能默认为PASS。

未质检是 NOT_ASSESSED，不计为合格。保留既有开发身份登记/初始标识标签能力；一旦QC登记，FAIL/PENDING/身份问题、撤销或返工状态即隔离，禁止其标签预览/重打及普通下游消费。未质检标签仅身份标识，不是放行证明。已输出纸面无法撤销。任何新交片/报告/扫描发布消费接入前必须明确要求当前有效PASS，不能把本任务的登记兼容路径当作放行。

## 隔离、撤销与历史

当前有效性同时检查材料版本、状态、源蜡块状态及QC、技术来源版本/状态。BLOCK隔离影响其玻片的后续消费，保留后代实体和旧判定以追溯。撤销QC需要当前QC版本、核对材料UUID和原因；撤销后阻断，重新评估必须新建判定。身份错误不得通过普通PASS或异常放行覆盖，只能保持隔离并按身份核查流程处理；本版本不提供身份更正或解除身份隔离。

QC、材料变更、标签和技术命令共同锁定申请，原子重查当前授权、状态、版本和来源；判定、隔离事件、审计与幂等回执同事务。已成功的历史消费不会倒写为未发生；后续预览/操作必须检查最新有效性。

## 返工

FAIL/PENDING/REVOKED/INVALIDATED可发起明确返工，身份错误不能。常规材料返工创建关联原技术任务的新UUID任务，保存原材料/判定/原因，原QC转为REWORK_REQUIRED，原实体不覆盖。返工任务需独立PROCESS权限并沿用T12领取、合成完成协议；完成不是QC通过。原片重切/加深沿用T13新玻片协议，明确选择所关联的新切片任务；新玻片仍需独立QC，不继承旧PASS。源蜡块隔离不得借玻片返工绕过。

直制材料没有盒级任务，不能伪造技术返工；本版允许另建明确直制实体并单独QC，原实体及隔离历史保持。冰冻及其他特殊返工路径待批准。

## 异常放行

医院审批角色、资格及规则未定，因此所有异常放行默认且持续禁用，服务端明确拒绝并展示原因；管理员也不能绕过身份错误。只预留显式拒绝的开发入口与验收，不模拟批准、不赋予管理员特殊权限。后续启用必须有独立授权、批准策略版本、原因、资格和原子审计验证，不能仅改前端按钮。

## 验收与边界

独立QC权限依赖READ，所有入口重新校验组织/病例范围。批量通过、交片批次、设备QC、临床诊断放行、真实医院阈值不在本任务。接口白名单、版本CAS、幂等同键异参/撤权重放、跨病例来源替换、审计失败回滚、撤销与标签/材料消费竞争需真实PG测试。UI展示未知/通过/不合格/待定/身份问题/撤销/返工/失效，并验证脏表单、迟到结果、原键重试及真实UI/API闭环。增量迁移，不改V1–V11；验证分支 validation/t14-20261002 全门禁后单项main。
