# T11 开发规格：取材描述、合成图像与取材盒 V1

2026-10-02。用户授权补充开发PRD，依据已查看 UI-008/009。仅合成dev/test，默认关闭；不表示临床取材/岗位或流程获批。

- 从已接收申请进入取材，病例由T09服务器关联，不接受客户端患者/病例替换。每开发病例一份取材记录；独立GROSS权限且要求READ。病例/容器未接收、范围无权、身份不符一律阻断。
- DRAFT→COMPLETED表示取材记录完成，不表示脱水/包埋/制成蜡块；DRAFT可带原因取消为CANCELLED。已完成仅可带原因更正描述，追加修订、不回写旧版本；盒/图像在完成后不再修改。本版没有临床双人复核资格流程，不伪造复核人。
- 大体描述0–8000字，完成时必须非空；创建/编辑/更正均保存独立修订。编辑、更正、取消必填原因，当前actor来自服务器。
- 取材盒是后续处理的稳定实体 UUID＋开发显示号DEV-C-UUID，不是已制备蜡块。每盒绑定同病例1–20个已接收来源容器，允许同容器拆入多盒、同病例多容器入一盒；跨病例/医院混盒拒绝。保存后来源谱系不可换；描述/块数由新增盒时保存，本版修正盒需带原因取消旧盒并新增。取消不删关系。
- 每记录最多50盒（含取消盒），部位1–255、材料块数1–99；这些是技术边界，不是临床取材建议。完成至少一个未取消盒。T12建立处理/包埋记录及实际蜡块，T13建立玻片；本任务不提前生成或标记这些实体完成。
- 图像开发范围仅接受随程序发布的固定合成PNG样本字节，拒绝其他图片/任意上传/URL；不接真实患者照片。UI明确“合成示意图，不是真实标本照片”，可下载样本并回传或直接选择样本测试附件闭环。不得把此白名单样本功能宣称为通用临床照片上传。
- 受控图像固定256×160，最多16KiB；base64最多22000字符，附件HTTP JSON请求体在解析前最多32KiB（含分块传输）；解码后逐字节/摘要验证白名单，无需解析不可信图像。拒绝SVG、脚本、扩展名伪装、不同PNG、超限、损坏内容。每记录最多5图（含撤回图），每图绑定确切已接收容器；备注0–255。
- 存储通过只读合成对象存储接口，私有classpath资源不在web静态目录；PG只存对象key、SHA256、字节数、尺寸和关联，不存图片BLOB。对象预置不可改，因此附件事务失败无外部半成品；替换成真实私有对象存储需独立安全验收。
- 附件下载先重新鉴权/检查关联与撤回状态，no-store、nosniff、PNG类型；客户端blob URL只在内存，切记录/关闭/退出撤销。撤回图片需要原因、记录事件并阻止新下载，原对象和关联不删除。
- 所有写命令包含资源ID、expectedVersion（创建校验申请版本）与完整输入的幂等摘要；同事务描述修订/盒谱系/图像元数据/追加事件/审计/回执。锁按既有主体→scope→grant→申请→取材记录顺序；并发旧版本拒绝，未知结果保留原键/输入。
- 列表/盒/图片/历史有界，错误不当作空态，不自动创建患者或病例；表单脏输入、切换、关闭、双击、断网、过期登录均沿用开发安全边界。V8增量迁移，不改V1–V7；独立验证分支完整CI通过后T11单独整理main。

待医院确认：取材/复核岗位与资格、描述规范、取材策略与数量、固定条件、照片同意/去标识/留存、真实对象存储及上传隔离、盒号与设备、重取/补取流程、交接与质量控制。未知政策保持开发限制，不默认临床放行。
