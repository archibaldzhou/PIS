# ADR 0008：复核依赖快照与合成模拟签署

2026-10-03，依据[T18开发PRD](../prd/development-report-review-v1.md)实施；没有医院签署规则批准或临床电子签名授权。

T17草稿编辑仍仅当前ACTIVE合格持有人。复核通过DiagnosisService的新公开边界授权同范围的合格医生，再检查独立report_review_grant，不把分配权、角色或管理员当签署权。scope必须显式配置不可变SYN-REVIEW-1策略，分别决定作者/复核者、复核者/模拟签署者是否分离。策略无默认记录；合成dev/test门禁和默认关闭配置不变。未来医院规则需独立批准，不扩展此合成策略语义。

每条复核事件指向确切报告修订，修订不可变且绑定模板。事件保存依赖摘要和原始依赖证据（分配状态/版本、当前持有人资格、材料/QC/技术任务快照、策略），另保存操作者资格快照。授权快照不含密码或令牌。摘要只用于相等性校验，不是数字签名。独立序列提供workflow_scope、workflow_grant、diagnosis_grant及report_review_grant的单调代次；更新甚至撤销后恢复均改变代次，防止旧复核重新就绪。账号使用已有auth_version。序列回滚出现空洞允许；不把连续编号作为业务要求。

此实现保守绑定整个申请的材料与QC/技术来源，相关变化可能使同申请另一病例的旧复核也失效。这避免遗漏祖先材料/返工依赖；后续优化必须有完整谱系和竞态证据。质量快照通过QualityGate公开接口提供，不跨域读取内部实体。读取持申请共享锁，命令沿用T07短事务与申请更新锁，锁后重新授权并验证所有输入版本。授权锁等待后再检查有效期。CAS、事件、审计和回执一起提交；完整Java锁竞争测试仍待依赖恢复。

APPROVE的就绪是当前派生状态，不是永久标志；旧事件不删除。RETURN必须保留原因且同一修订不能再通过，需作者新建修订。SIMULATE_SIGN只能消费当前有效APPROVE，记录原复核ID与自身资格，CAS保证同一头只有一个获胜命令。模拟后头与草稿冻结，数据库触发器和服务双重拒绝覆盖；新更正、PDF、发送、CA均不在本次范围。后续QC或资格变化不篡改模拟历史，也不会返回ready=true。

复核历史独立按20条分页；界面切换页不重置操作表单。原请求未知时冻结并用原键原快照确认，冲突保留输入供人工重新核对。实际测试与阻塞见[T18交付记录](../api/t18-development-status.md)。
