# ADR 0006：合成诊断分配资格与就绪门禁

2026-10-03，T16 开发决定。用户明确要求继续本地开发、不等待 GitHub、不修改 OAuth 或安全配置；接口使用既有受保护的 `/api/requests/diagnosis` 子路径，保持 SecurityConfiguration 字节不变。旧 workflow READ 不自动授予诊断功能，新增 diagnosis_grant 的人员/范围/有效期/合成资格和独立分配、本人处理权限。生产迁移不种任何资格，测试账号配置仅在 test 源码内。

分配对象采用既有 caseId，一病例一个当前分配记录，初始不存在为 UNASSIGNED/-1；ASSIGNED 必须本人领取后才 ACTIVE，转交回 ASSIGNED。不赋予报告编辑、签发或管理员抢占能力，也不代表临床执业资格验证。医院资格制度尚待批准。

DiagnosisService 单向依赖 RequestService/WorkflowAccess、QualityGate 和 T07。当前小型模块化单体使用病例/分配最小读投影，队列 count 与 page 同 SQL 快照，独立一次批量就绪查询最多50病例，不逐病例往返查询。QualityGate 暴露授权调用方使用的诊断就绪边界，复用 V13 有效QC投影。没有改变标签早期身份登记可允许 NOT_ASSESSED 的既有兼容规则；诊断流转要求 ACTIVE 玻片存在、所有 ACTIVE 材料有效 PASS、无申请身份隔离。旧身份异常不得靠作废材料清除。

写命令使用原 T07 事务。资格/账号/范围共享锁后取得申请根锁，再复核身份/版本/当前人员/资格期限/接收状态/QC；同请求的材料和QC写遵循既有根锁，因此门禁与消费串行。分配记录CAS、追加事件、审计、幂等回执原子提交；目标资格撤销等待后重新读取。发生在流转之后的QC撤销保留既有归属历史，阻止下一次流转，不自动创造临床动作。历史幂等回执不代表当前仍然就绪，UI必须刷新。

V14 扩展新增表/约束/触发器，不改 V1–V13。qualification 仅 SYN-DIAG-ASSIGNMENT-1，资格管理API和真实证照核验未实现，合成测试夹具按明确范围配置。诊断事件只追加；当前分配身份不可变，更新必须恰好增加一个版本。真实规模索引/查询容量和生产权限仍需验证，本次不作医院性能或合规承诺。
