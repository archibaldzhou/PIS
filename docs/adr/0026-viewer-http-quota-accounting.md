# ADR 0026：阅片频次按物理 HTTP 请求计量

状态：T36 修复；完整 CI 待验证。限额值、专业授权和临床边界不变。

CI 37174679421 证实重显结果 PNG 返回 VIEWER_RATE/429。调用链为 AiResultService.tile → 两次 current/source → task.detail（3 次 manifest 依赖检查）及 task.artifact（4 次 manifest 依赖检查）。一次 PNG 因此消耗 14 个 viewer_read_budget 请求单位；metadata 消耗 7 个。内部核验与底图、导航器的真实请求共用计数，造成正常操作被错误放大计费。

保留所有 authorize/unchanged/QC/模型/身份核验。仅在 Servlet 请求属性中记录当前用户已成功扣减的频次，不保存任何可复用的授权决定；客户端头无法设置此属性。独立 HTTP 请求、独立用户重新计量；非 HTTP 调用保留原逐调用计量和事务语义。请求标记随请求释放，无全局缓存或 ThreadLocal。

同一 HTTP 请求内后续零字节依赖核验不再次扣频次，真实二进制字节仍逐次扣减。上限仍为 240 次/分钟、33554432 字节；同一请求采用首次计费窗口，跨分钟不再次收取一个请求单位。内部并发计量同步，最多保留16个用户条目。

原 ddb6419 使用 REQUIRES_NEW 独立计数；CI 37176249592 的资格/ROI GET 出现500。源码确认这两个入口本身是可写事务（GET 不等于 readOnly），持有连接及病例锁后再次借连接。在默认5连接池下，其他请求占用剩余连接时形成嵌套连接饥饿路径。本地缺少Spring依赖，且父会话暂未提供异常类，因此不能声称已确认该次CI具体异常链。

修正为 REQUIRED：已有业务事务时计数与审计共同提交/回滚，没有外层事务时自行提交短事务。不额外占用连接，不修改连接池或限额。只有计数成功才设置请求内标记；参与外层事务时登记 afterCompletion，在回滚/未知完成状态撤销该次频次与字节标记。早先已提交的频次不因后来字节事务回滚而撤销；回滚后的再次读取须重新计费。失败事务不交付图像且不留部分审计或计数，回到原业务事务语义。所有逐次授权与QC校验不变。读操作包含锁定及审计，不改成只读；误入只读事务必须失败且无持久写入。

真实HTTP回归在登录及夹具初始化后持有5个连接中的4个，依次请求资格及ROI：余下一个连接必须完成、分别计1次；错误发布版本返回409、撤权返回404。此前独立事务设计需要第二连接，必然无法满足该测试。另有回滚标记、同请求QC撤销及readOnly失败关闭回归；完整Spring测试由CI验证。

响应 `X-Viewer-Quota-Checks`/`X-Viewer-Quota-Units` 仅含本次请求的数字，不含身份、病例或剩余全局配额。VIEWER_RATE/429 增加 1–60 秒的 Retry-After（当前固定分钟窗口的剩余时间）；不自动无限重试。所有缓存命中仍重新授权。

回归包括实际 HTTP 生成一次扣1单位、metadata+PNG每轮扣2单位、重显字节不变、240边界429、伪造计量头无效、Retry-After、业务回滚及已计量请求内QC撤销。原权限、隔离、像素、审计失败和字节上限检查不减弱。
