# ADR 0032：集中管理合成账号、授权与自动工作区

日期：2026-10-07。状态：按本会话授权实施，限合成开发环境。

用户要求将人员、角色、权限和工作范围配置移到后台，普通工作流不再选择授权范围。沿用 Cookie 会话、CSRF、JDBC、Flyway 和已有各域授权策略，不引入身份中间件或前端权限依赖。

## 决定

- `identity` 域提供医院级管理用例。角色是服务器内置、可读的岗位模板；用户各范围的具体权限可调整，保存时映射到已有显式授权表。角色名不替代资源级鉴权。
- 医院管理员授权独立于临床/合成专业资格。管理员默认获得全部非专业功能；诊断、复核、模拟签署仍须显式核验资格，不改变作者与复核人员分离等策略。
- 管理写入使用医院、管理员、目标账号的统一锁序，目标版本 CAS；授权、变更快照、成功审计和幂等回执在同一事务提交。账号变更增加认证版本，旧会话失效。禁止修改自身管理权限，避免单人撤销最后一位管理员。
- 新增/重置的密码必须首次修改。修改本人密码校验旧密码，在同一事务追加审计并递增认证版本，完成后重新登录；未知结果通过重新登录确认，不自动重复密码变更。
- `/api/requests/work-context` 返回默认范围和当前有效菜单、可写范围。申请列表可不传 scopeId，此时在服务端按有效授权合并分页；既有申请始终使用其持久化范围。其他队列继续使用后台配置的默认范围。
- 单范围历史合成账号可自动使用唯一有效范围；多范围历史账号没有默认配置时阻止进入工作区，不能随意选择第一个范围。默认范围失效时明确要求后台修复。
- `report_output_grant` 将固定报告输出和本地投递与诊断编辑、复核、签署分离。保持冻结版本依赖与签署人员资格校验。新增纯管理字段 `workflow_scope.admin_version` 从既有资格快照中排除，避免仅迁移字段就使既有快照变化。
- 业务拒绝和授权拒绝的管理 HTTP 请求在独立事务追加 `identity_denial_event`，只含主体、请求医院、错误码、trace 和时间。认证/CSRF/绑定格式错误仍沿用既有安全日志，尚不是完整持久安全审计覆盖。

## 边界

本次不修改病例策略、不默认启用新范围的报告复核策略、不引入 SSO、CA 签名、真实医院账号同步或生产部署。人员资格确认由合成后台管理员显式操作，不代表医院资质核准系统。分子病理角色只展示未开放，不虚构模块。

迁移不生成管理员。显式本机初始化工具仅在测试 classpath，限定本机 `pis_test`、随机测试 schema、既有启用合成账号及唯一范围；已有管理员时拒绝再次初始化。生产首个管理员及旧账号迁移另需受控方案。

验证和运行见 [管理接口与验收](../api/identity-administration.md)。
