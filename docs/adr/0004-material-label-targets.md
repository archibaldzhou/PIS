# ADR 0004：材料身份接入现有标签协议

状态：T13 开发采用；2026-10-02。适用合成 dev/test，不是生产迁移批准。

材料需要独立稳定条码，同时保持 T10 容器标签、重打历史和幂等语义。新增材料标签服务会分裂条码唯一性、状态和权限，因此扩展同一 label_identity/job/event，增加互斥 material_id/container_id 及生成 target_id，并保留旧容器字段、外键和索引。材料 UUID 独立，显示号不用 max+1，首次材料创建即登记唯一条码，重打不创建材料。

label 定义公开 LabelSubjectProvider 接口；容器和材料实现各自授权快照，label 不依赖 material。material 通过 label 公开登记接口（强制已有事务）创建身份，避免服务循环依赖。processing 和 specimen 提供最小公开来源投影，材料不引用它们的内部 Repository。前端材料页面通过 labels 公共入口复用预览及状态操作。

标签 Job 新增 materialId/targetId，containerId 对材料为 null；旧容器响应字段保持原义。数据库 container_version 历史列暂兼容存目标版本，新增材料创建 DTO 使用 materialVersion，不改旧 DTO。旧模板仅允许容器，新模板仅允许材料。复合 FK 保证标签/谱系目标一致；全局唯一条码及 target_id 禁止身份混淆。

V10 对现有标签表增加生成列、约束及替换主键，需要表锁和生成列物化；现有数据仅为开发小库。验证空库与 V9 旧标签升级、历史快照/事件、旧迁移校验和。未做真实大表耗时/锁评估；生产前需按实际规模拆分 expand、回填、验证和 contract，并评估维护窗口、备份恢复。失败事务回滚，成功迁移优先向前修复，不改已执行 V1–V9、不用 Flyway repair/clean。

申请行作为跨材料/技术/标签写入共同锁，避免材料作废与重切、重打并发造成新有效后代。锁和事务沿用 T07 超时。纯软件无法证明实体实际制作或撤销已输出纸面，UI 明示合成登记和预览边界。

V11 修复生成列的触发时机：存储生成值在 BEFORE 触发后计算，V10的整行比较因 NEW 中生成值尚不可用而误拒绝普通更新。将两个相关触发器改为 AFTER UPDATE，原不可变比较函数与字段保护均保留；错误在同一SQL语句内回滚，不产生外部副作用。其他取材/历史触发器不变。V1–V10已执行文件保持原样，升级回归保留确切校验和。
