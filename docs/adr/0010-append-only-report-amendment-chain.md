# ADR 0010：补充／更正新草稿及不可变版本链

状态：T20 合成开发实现，非医院临床规则批准。依据[先行开发 PRD](../prd/development-report-amendments-v1.md)。

## 决策

补充 ADDENDUM、更正 CORRECTION 各自明确记录类型及强制原因。原报告为隐式链版本 0；每次新建产生 report_amendment ID（独立逻辑草稿 ID）、全新 report_revision ID 及递增的病例修订号。初始字段、模板复制自确切原冻结修订，随后按 T17 人工编辑；不自动生成诊断，也不继承原复核。

V18 只新增分支、链头、替代关系，并替换两个保护“当前指针”的触发器函数。旧 report_revision、report_review_event、report_artifact 及 audit_event 的不可变约束不变，V1–V17 文件不改。report_draft 是当前修订指针，不是冻结原文；原文仍按不可变修订 ID 查询。只有匹配原签署、当前草稿、父分支、链序号和新起始修订的显式分支可推进被冻结的指针，不能直接解冻原文。

请求根行 FOR UPDATE 序列化创建、保存、复核、QC 和分配用例。分支唯一原签署后继、唯一病例序号、唯一父分支以及链头 CAS 拒绝分叉。未完成新草稿不能继续创建分支；目前不实现已提交分支的撤销/删除，UI 的取消仅作用于本地输入。报告修订号及复核事件号继续按病例递增，不重置、不删除原头或原事件。纯数据库约束不是对特权管理员的不可篡改证明。

新建时重新校验当前领取人、医生资格、病例/组织作用域、分配版本、QC/身份状态和复核范围。旧签署依赖已过期不阻止合格人员在当前门禁恢复后创建更正，但不使旧复核复活。新修订改变 T18 依赖摘要，必须重新执行其显式策略与资格检查、复核和合成模拟签署。不能靠管理员角色取得权限。

新签署与 report_replacement 同一 T07 命令事务追加，替代关系绑定分支、原签署及新签署；审计失败回滚签署、头和替代关系。新签署前，原冻结版仍为当前冻结版；新签署后才显示旧版被替代。下游状态只允许 PENDING_NOT_SENT，既不是 outbox 投递，也不是 ACK 或临床送达确认。T21 需独立设计投递/确认事件，不应就地改写本次关系。

T19 新产物按新签署唯一生成，旧字节/哈希不动。历史产物元数据新增显式资源接口，访问仍校验当前病例/组织/医生及复核资格。二进制继续经审计 POST 返回同一字节。历史 UI 校验病例、产物 ID、签署、修订及修订号后才显示，下载仍验证字节摘要；不能把新版元数据/字节串入旧版。新打印请求额外检查产物签署恰是当前冻结签署，不能借新版就绪打印旧版。

## 界面及限制

授权 UI-023 的原版只读、新版类型/原因和时间线要素落到现有工作区。创建草稿后继续使用 T17/T18/T19 人工流程；历史查看和创建表单互斥，防止一个表单完成时清除另一个表单脏状态。切病例、分页、历史选择及离开均处理未保存输入；未知请求阻止切换，原键确认。旧版、当前冻结版及待完成草稿明确区分。

无新增生产依赖、字体或渲染器变更；合成模式默认关闭。不发送、不使用实体打印机、CA、真实患者或 AI。T20 不声明临床/法律签署效力。完整后端构建及真实服务 E2E 尚受 Maven BOM 缺失阻塞，实际验证范围见[交付记录](../api/t20-development-status.md)。
