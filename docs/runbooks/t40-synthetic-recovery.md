# T40 合成隔离恢复操作与边界

运行 `python3 scripts/synthetic-recovery.py`。需要本机 Docker 与固定 PG17 镜像；不接收数据库地址、密码、目录或恢复目标参数。不提供生产恢复开关。

脚本总预算150秒（清理另限15秒），CI步骤3分钟；每个子进程也有上限。工具自行创建无网络、512MiB/1CPU、tmpfs 数据目录的临时容器，以及 0700 临时目录。应用不运行，数据库与文件没有并发写者；V1–V37 迁移后只插入固定合成身份、禁用且没有可用口令的合成账号、一个约2MiB对象及相应审计/幂等记录。真实 `pg_dump -Fc` 使用一致数据库快照，清单绑定每个迁移 SHA256、dump SHA256、根 UUID、对象 UUID/大小/SHA256。此流程不声称支持在线业务库快照。

完成清单以前为 INCOMPLETE；验证拒绝缺失、损坏、符号链接、额外文件、错误版本、旧目录和目录外目标。只恢复到自身创建的全新数据库和目录；已有、部分完成的目标不会重用。`pg_restore --single-transaction --exit-on-error`；故障注入通过真实 advisory gate 暂停首个 DDL 并终止恢复连接，验证事务无业务表残留。中断库在演练内隔离，不覆盖原库，再恢复到另一个新库。逐表摘要核对全部145表，显式核对身份链、审计、幂等回执与 READY 对象/root引用和原字节。

退出只清理本次 random-name 容器与临时树，不接触已有库/用户文件。完整 dump/对象/数据库输出不打印、不提交、不作为 CI 制品；唯一证据是固定代码、数量、耗时与合成对象摘要。没有患者数据、可用凭据、加密密钥或远端调用。

加密、异地备份、实际应用在线恢复、生产角色/权限重建、医院 RPO/RTO 全部未配置/未验证。本脚本有意不是任意数据库备份工具；不得用演练通过代替医院恢复验证。应用 UI 的当前实例恢复状态保持 NOT_VERIFIED，不读取此演练结果伪装实例健康。
