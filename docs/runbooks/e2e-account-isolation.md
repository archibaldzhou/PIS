# 合成 E2E 账号隔离

真实浏览器工作流按 `*.spec.ts` 文件分配独立的工作流/交接账号对、医院及工作范围。同一文件中的不同浏览器上下文仍单独执行真实登录，不共享 Cookie、保存的认证状态或持久化令牌。复核、交接等角色仍使用不同主体；既有权限和职责分离规则保持不变。

账号由测试 classpath 的 `E2eFixtureConfiguration` 在一次性 PG 测试 schema 内创建；生产包不包含该种子。`PIS_E2E_WORKFLOW_USERNAME` 和 `PIS_E2E_HANDOFF_USERNAME` 如有设置，现作为用户名前缀，追加 `.<文件名>`，总长不能超过 64。密码环境变量仍仅用于合成测试种子；此变更不创建生产账号或凭据。

新增工作流文件须加入种子的 `WORKFLOW_SCENARIOS`，调用 `signInWorkflow`，第二参与者使用 `handoffUsername()`。前端单测核对种子与文件一一对应，并阻止回退到共享交接账号。认证错误套件 `hello.spec.ts` 保留独立 reader/disabled 身份。

产品登录限流保持每账号 20 次、每来源 IP 100 次/5 分钟。没有重试、sleep、限流配置变更或串行化变更。套件预算单测在单文件或总登录预算接近上限时要求重新审查夹具；它不是实际请求计数器，不代替真实 E2E。后端新增回归验证超过 20 个文件的账号隔离，以及独立账号仍不能绕过原有账号/IP 上限。

本次本地证据：130 项前端单测、lint、类型检查及构建通过；实际种子 SQL 经 PG17 V1–V24 验证为 19 个独立范围、40 个合成账号，每范围恰好两名有区别的参与者。实际限流类独立 Java 探针通过原有 20/100 边界。种子探针使用 JDBC/编码器替身提取 SQL，不替代 Spring 集成测试。

本地 Maven verify 因离线缓存缺少 Spring Boot 导入 BOM 而停止，完整后端及真实 E2E 未在本地执行。本提交 CI 须另行核验；T27 未提交代码不属于本次修复。
